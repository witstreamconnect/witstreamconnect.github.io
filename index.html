The problem
Drilling data speaks six dialects, and nobody agrees on the words
Every rig, every contractor, every service company can speak a different protocol, and often a different naming convention for the exact same measurement. A multi-year campaign can span several contractors on one well. Most platforms in this space pick one format, convert it one way, and charge a services engagement every time that changes.
WITStream Connect® fixes this by normalising every protocol into one canonical model first: every source writes into the same shape, every sink reads from it, so a new rig or contractor's own numbering is a settings screen your own staff can change, not an integration project.
That's how WITStream Connect® removes that cost entirely.

Getting Started
From licence key to live data, in three steps
Everything here reflects the real product, not a simplified version of it. If something here doesn't match what you're seeing, that's worth a message to support, not something to work around yourself.
01
Get a licence and deploy the container
Sign up through the customer portal, pick a tier, and a licence key is issued straight away. Deploying is one line, run on your own infrastructure, on-premise or your own cloud account, nothing is hosted for you:
curl -fsSL https://witstreamconnect.com/install.sh | bash
The install script asks for your licence key once, generates a random API key for your own dashboard, and never touches an existing configuration on a later run, so re-running it is also the correct way to pick up an update.
02
Map your first connection
Open the configuration screen (linked from your own dashboard), add a connection, and pick a source: WITSML, WITS0, ETP, OPC-UA, Modbus, or a LAS file folder. Each source type reveals only the fields it actually needs. If your rig's own mnemonics don't match the standard set, the mnemonic map translates them, this is the same settings screen that reconfigures for a completely different contractor's channel numbering with no code changes.
Optional output sinks (CSV, or re-emitting in any of the other five formats) toggle on the same screen. A saved change takes effect on the next restart, the install command above is also the redeploy command.
03
Watch it run
The live dashboard shows every connection's live state. Transferring means data is genuinely flowing; reconnecting means a connection dropped and is retrying on its own, no action needed; a plain suspended badge with a message means it needs a look, usually a specific, readable reason (an unreachable address, a rejected credential) rather than a generic failure.
Common questions
A connection shows "suspended", what do I do?
Read the status message next to it first, it's a specific reason, not a generic error. Most causes are an address or credential issue on the source system itself, not something wrong with the deployment. It will keep retrying on its own; nothing else stops running while it does.
Can I change tiers later?
Yes, from your account overview in the customer portal. Nothing about your configuration needs to change, tiers only govern how many rigs can connect at once.
Does reconfiguring for a new rig need a developer?
No. A different contractor's channel numbering, a different unit set, a different protocol entirely, all of it is the same settings screen described in step two above, with zero code changes.
